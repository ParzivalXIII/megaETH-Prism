The daemon handles malformed data at three protection layers:

LAYER 1 — Malformed JSON (json.JSONDecodeError)
  The `_message_handler()` method wraps `json.loads()` in try/except.
  If the WebSocket emits non-JSON data:
    -> Logs: "malformed JSON from WS, skipping"
    -> Increments: ws_subscription_errors_total
    -> Continues to next message (stream not polluted)

LAYER 2 — Non-subscription messages
  Keepalive replies and other JSON-RPC responses have
  `method != "eth_subscription"` and are silently ignored:
    -> Logs: "ignoring non-subscription message" (DEBUG level)
    -> Continues without any counter increment

LAYER 3 — Pydantic MiniBlockPayload validation
  Even valid eth_subscription messages are run through
  MiniBlockPayload.model_validate(). If the payload doesn't
  match the schema:
    -> Logs: "miniBlock failed structural validation, skipping"
    -> Increments: ws_subscription_errors_total
    -> Stream is not polluted with malformed data

  NOTE: The current MiniBlockPayload schema expects int fields but the testnet
  returns hex-encoded strings. Pydantic validation rejects these payloads,
  which is CORRECT behavior — the schema defines the data contract,
  and non-conforming data is safely discarded without crashing the daemon.
